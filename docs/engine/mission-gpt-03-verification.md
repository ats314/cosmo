# Mission GPT 03: flight continuity and audio reference verification

2026-09-07. Antigravity is Lead Agent. This mission changes verification and

is unchanged. No native engine files were edited and no Godot process ran.

## Flight audit result

**Completion-card entry and dwell preserve position continuity. Choosing the
next level still resets the comet.** Those are separate boundaries; passing
the glide check does not certify the whole transition as continuous flight.

- `runtime.js:3628`: `levelComplete()` changes state without changing angle,
  direction, ring, hop progress or presentation time. A controlled mid-hop
  completion produced zero immediate position or clock jump.
- `runtime.js:7818`: hop interpolation advances before the card's early
  return, so an unfinished hop settles normally during the card.
- `runtime.js:7912`: the card adds `0.8 * dt * G.dir` to the existing angle and
  records the actual position in the original tail. It does not wrap or reset
  coordinates. A separate 30-second dwell at direction -1 advanced -24 radians
  within floating-point precision.
- `runtime.js:12341`: forward distance comes from `G.vt * 100`, so it keeps
  advancing during the card. Reduced motion suppresses decorative travel while
  preserving the playable comet. Existing slow-motion easing still affects
  `G.vt`; card angular motion uses raw frame delta.
- `runtime.js:7332–7355`, `6227–6228`: an actual upgrade-tile pointer selection
  calls `cardDone()` and `startGame()`. The latter resets angle to `-PI/2`,
  direction to +1, ring to 0 and hop progress to 1 even on a carried level.
  A level-2-to-3 probe measured a **384.332 CSS-pixel position jump** in a
  390×844 viewport, with **zero** change in visual time or forward distance.
  This is existing source behavior, not introduced by the flight renderer.
- The added 3D wake is restricted to `playing` and clears during the card
  (`flight-world.ts:343`). Dust and strands continue; the original 2D tail
  also continues. That clear prevents a false wake connection across the later
  position reset. Extending the wake through cards needs an explicit reset on
  actual repositioning because the visual clock alone does not detect it.
- Playing pause and count-in freeze position and visual time. The card has no
  pause button and is outside the source's in-game pause gate; host/background
  suspension remains a separate concern.

The native wormhole implementation should carry its current position and
journey through its transition. It should not treat the original next-level
`startGame()` reset as evidence of smooth spatial continuity. Changing that
web reset is separate from this source-parity audit; no gameplay fixture was
re-recorded to conceal a behavior change.

## Added glide regression coverage

`tools/lib/flight-transitions.mjs` runs through the existing `flightcheck`.
It covers all five completable levels, both directions, settled and unfinished
hops, normal and reduced motion, slow-motion recovery, mixed frame deltas,
zero-delta steps and the host's 50 ms stall clamp: **40 cases, 6,000 steps**.
Each case spans 3.45 simulated seconds. It checks angle, Cartesian position,
hop settlement, clocks, tail alignment and unchanged score during the card.

This supplements the original **3,482 trajectory frames**, 191 function hashes
and 11 tuning tables; their baseline is unchanged. Independent in-memory
mutations of the runtime were rejected for frozen glide, a coordinate snap at
completion and a frozen presentation clock. No mutated runtime was written.
These are state/geometry checks, not rendered smoothness or iPhone performance
measurements. The longer dwell and actual pointer-selection probe are local
evidence under `work/mission-gpt-03/level-card-probe.mjs` and its JSON output.

## Audio reference maintained and extended

Run `node db/export-native-audio-reference.mjs`. The default local output is
`work/godot-collaboration/original-audio-reference.json`.

All **18 Starfall and 432 movement scenarios** remain unchanged, as do their
source tables and previous origin records. Additional assertions check the
actual authored note frequencies and onset times. The exporter now adds
`synth_reference`, format `cosmo-original-synth-trace-v1`, containing **14**
scenarios generated by executing the original `note`, `hat`, `kick`, `snare`
and `bassN` functions in a separate recording context:

- One fixed kick: 400→48 Hz exponential sweep in 0.075 seconds, with the
  original gain envelope and oscillator stop time.
- Six keyed snares: triangle body at `CH[0][0] * 1.7818`, plus the actual
  1900 Hz high-pass noise path and envelope.
- Six bass voices: saw at the fundamental, sine one octave below and square
  one octave above, retaining each gain, duration and filter envelope.
- One actual first-tap player note, including its dry bus, reverb and echo
  connections.

Each scenario records `id`, `voice`, `level`, `inputs`, `nodes`, `events` and
`connections`. Events retain AudioParam method names and argument times;
origins additionally identify the five primitive source functions. Native
audio can compare against these records without copying a replacement melody.

All 14 traces were independently compared with the **full original runtime**
in the existing music sandbox, with zero differences. Six mutation checks
rejected wrong kick frequency/ramp type, fixed snare pitch, changed bass
sub-frequency/gain and altered note attack. The two unchanged JSON sections
have these SHA256 hashes:

| Section | SHA256 |
|---|---|
| `tables` | `19cd820fd232e1d5054095c4f163ffddd021705e0710ea79f81c9579b0ed6a49` |
| `levels` (all 450 scenarios) | `456892911c5c873f2031e222e9254305d3f13f7708ad24f9b69fa437aed7f69d` |

This records control calls and graph structure. It does not render PCM, noise
samples, DSP interpolation, master effects or native scheduling. The full
ordinary arrangement is still outside this exporter. Native audio parity and
device timing cannot be certified merely by generating these references.
